# Техническое задание: игра «Крестики-нолики 5×5» с ИИ

## 1. Цель проекта

Разработать небольшую desktop-игру «Крестики-нолики» на Python с графическим интерфейсом на `tkinter` + `ttk`.

Игрок играет против компьютера на поле **5×5**.

Проект должен быть:

* простым для запуска;
* понятным для начинающего Python-разработчика;
* разделённым на логические модули;
* без сторонних зависимостей;
* пригодным для дальнейшего расширения;
* покрыт базовыми автоматическими тестами для игровой логики.

Главный приоритет — **корректность игровой логики, простота архитектуры и понятный код**, а не сложность ИИ.

---

# 2. Технологический стек

Использовать:

* Python 3.11+;
* `tkinter`;
* `tkinter.ttk`;
* стандартную библиотеку Python;
* `unittest` или `pytest` — предпочтительно `unittest`, чтобы не требовать сторонних пакетов.

Запрещается без необходимости использовать:

* внешние библиотеки машинного обучения;

Приложение должно запускаться обычной командой:

```bash
python main.py
```

# 3. Игровые правила

## 3.1. Игровое поле

Поле имеет размер:

```text
5 × 5
```

Всего:

```text
25 клеток
```

Игрок использует символ:

```text
X
```

Компьютер использует:

```text
O
```

Игрок ходит первым.

---

## 3.2. Условие победы

Побеждает тот, кто первым собрал **5 своих символов подряд**:

* по горизонтали;
* по вертикали;
* по диагонали слева направо;
* по диагонали справа налево.

Поскольку поле 5×5, для победы требуется заполнить всю линию длиной 5.

Примеры:

```text
X X X X X
```

или:

```text
X
X
X
X
X
```

или:

```text
X . . . .
. X . . .
. . X . .
. . . X .
. . . . X
```

---

## 3.3. Ничья

Если все 25 клеток заполнены и победителя нет — игра заканчивается ничьёй.

---

## 3.4. После окончания игры

После победы или ничьей:

* запрещается делать новые ходы;
* отображается сообщение о результате;
* предоставляется возможность начать новую игру.

---

# 4. Требования к ИИ

ИИ должен играть за `O`.

Не требуется реализовывать полноценный minimax для всего дерева игры.

Использовать простой **эвристический ИИ**, обеспечивающий разумное поведение:

### Приоритеты хода ИИ

ИИ должен анализировать возможные ходы в следующем порядке:

1. Если ИИ может выиграть текущим ходом — сделать этот ход.
2. Если игрок может выиграть следующим ходом — заблокировать его.
3. Если есть возможность создать собственную потенциально выигрышную линию — предпочесть такой ход.
4. Предпочитать центральную клетку.
5. Предпочитать клетки, увеличивающие количество потенциальных линий.
6. В остальных случаях выбирать допустимую клетку.

Для первого варианта реализации достаточно использовать следующие эвристики:

```text
Победа сейчас       → максимальный приоритет
Блокировка игрока   → очень высокий приоритет
Центр               → высокий приоритет
Потенциальные линии → средний приоритет
Остальные клетки    → низкий приоритет
```

# 7. Проверка победы

Реализовать отдельную понятную функцию/метод для проверки победы.

Алгоритм должен проверять четыре направления:


Даже если сейчас она равна размеру поля, сделать её отдельной константой, чтобы архитектура позволяла в будущем реализовать, например, поле 10×10 с победой при 5 символах.

# 9. Алгоритм ИИ

Реализовать функцию оценки хода.

Например:

```python
score_move(game, row, col) -> int
```

Рекомендуемая логика:

### Шаг 1. Проверка победного хода

Для каждой свободной клетки:

1. временно поставить `O`;
2. проверить победу;
3. если победа — выбрать клетку немедленно.

---

### Шаг 2. Блокировка игрока

Для каждой свободной клетки:

1. временно поставить `X`;
2. проверить победу;
3. если игрок победит — выбрать эту клетку для блокировки.

---

### Шаг 3. Оценка позиции

Для остальных ходов рассчитать score.

Примерная система:

```text
центр поля                  +10
участие в потенциальной линии +N
создание потенциальной линии +M
угловая клетка               +3
остальная клетка             +1
```

Конкретные значения можно подобрать так, чтобы поведение ИИ было разумным и детерминированным.

---

# 10. Детерминированность ИИ

По умолчанию ИИ должен быть детерминированным.

Если несколько ходов имеют одинаковый score, выбирать клетку по стабильному правилу:

```text
сначала row,
затем col
```

То есть:

```python
min(candidate_moves)
```

или эквивалентный порядок.

Не использовать `random` в базовой реализации.

Это упростит:

* тестирование;
* отладку;
* воспроизведение ошибок.

# 18. Игровой цикл

Последовательность действий:

### Старт

```text
Запуск приложения
        ↓
Создание Game
        ↓
Создание AI
        ↓
Создание UI
        ↓
Игрок делает ход
```

### Ход игрока

```text
Игрок нажал клетку
        ↓
Проверка допустимости
        ↓
Game.make_move()
        ↓
Обновление UI
        ↓
Проверка победы
        ↓
Проверка ничьей
        ↓
Если игра закончена → показать результат
        ↓
Иначе передать ход ИИ
```

### Ход ИИ

Использовать `after()` Tkinter, чтобы ход компьютера не выполнялся непосредственно внутри callback пользовательской кнопки.

Например:

```python
self.root.after(300, self.make_ai_move)
```

Задержка должна быть небольшой — примерно 200–500 мс.

Цель задержки — визуально показать пользователю, что сейчас ход компьютера.

Не использовать:

```python
time.sleep()
```

в UI-потоке.

# 19. Блокировка пользовательского ввода

```python

```

```text

```

После завершения:

```text

```

При обработке клика:

```python

```

После победы желательно визуально выделить пять выигрышных клеток.

Для этого игровой модели желательно возвращать не только победителя, но и победную комбинацию.

Например:

```python

```

Пример:

```python

```

UI использует эту информацию для визуального выделения соответствующих кнопок.

Если реализация подсветки через стандартный `ttk.Button` оказывается чрезмерно сложной из-за особенностей тем оформления, допускается использовать `tk.Button` **только для игровых клеток**, оставив `ttk` для остальных элементов интерфейса.

Однако предпочтительно сохранить `ttk` там, где это не ухудшает UX.

# 29. Критерии готовности

Задача считается выполненной, если:

* [ ] приложение запускается командой `python main.py`;
* [ ] открывается графическое окно;
* [ ] отображается поле 5×5;
* [ ] игрок может делать ходы;
* [ ] компьютер делает ответные ходы;
* [ ] компьютер не занимает занятые клетки;
* [ ] определяется горизонтальная победа;
* [ ] определяется вертикальная победа;
* [ ] определяется диагональная победа;
* [ ] определяется обратная диагональ;
* [ ] определяется ничья;
* [ ] после окончания игры новые ходы невозможны;
* [ ] отображается результат;
* [ ] победная линия подсвечивается;
* [ ] кнопка «Новая игра» корректно сбрасывает игру;
* [ ] во время хода ИИ пользователь не может сделать ход;
* [ ] ИИ блокирует немедленную победу игрока;
* [ ] ИИ использует выигрышный ход, если он доступен;
* [ ] центр имеет повышенный приоритет;
* [ ] нет `time.sleep()` в UI-потоке;
* [ ] игровая логика не зависит от Tkinter;
* [ ] написаны автоматические тесты;
* [ ] тесты проходят;
* [ ] отсутствуют внешние зависимости;
* [ ] имеется README.md.

# 30. Порядок реализации для Cursor

Работать итеративно.

### Этап 1 — игровая модель

Создать:

```text
constants.py
game.py
```

Реализовать правила и тесты.

Сначала добиться прохождения всех тестов `Game`.

---

### Этап 2 — ИИ

Создать:

```text
ai.py
```

Реализовать эвристический выбор хода.

Добавить тесты AI.

---

### Этап 3 — UI

Создать:

```text
ui.py
main.py
```

Подключить `Game` и `AI`.

---

### Этап 4 — интеграция

Реализовать:

* обработку кликов;
* ходы ИИ;
* `after()`;
* блокировку ввода;
* отображение результата;
* новую игру;
* подсветку победной линии.

---

### Этап 5 — проверка

Запустить:

```bash
python -m unittest discover
```

Затем:

```bash
python main.py
```

Проверить игру вручную.

# 31. Важные указания агенту Cursor

Не пытайся сразу написать весь проект одним большим файлом.

Сначала создай игровую модель и тесты, затем ИИ, затем UI.

После каждого этапа проверяй, что проект запускается и тесты проходят.

Не изменяй архитектуру без необходимости.

Не добавляй сторонние зависимости.

Не добавляй функциональность, которой нет в этом ТЗ.

Если обнаружишь неоднозначность, выбирай самое простое решение, соответствующее принципам:

* KISS;
* SOLID;
* separation of concerns;
* testability.

Код должен быть понятным человеку, который хорошо знаком с Python, но не является экспертом по игровому программированию.
