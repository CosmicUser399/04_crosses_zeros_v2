# Дополнительное техническое задание №2

# Система подсказки оптимального хода

## 1. Цель

Добавить в игру функцию:

> **«Подсказать ход»**

При нажатии пользователь получает визуальную подсказку, какую клетку рекомендуется занять следующим ходом.

Подсказка предназначена только для игрока и **не должна автоматически выполнять ход**.

---

# 2. Основной принцип

Подсказка должна выбирать наиболее сильный доступный ход для игрока `X`.

Важно:

> Подсказка не должна использовать алгоритм уровня сложности текущего AI напрямую как замену логики игрока.

Необходимо иметь общий механизм оценки/поиска:

```text
Game
   ↓
Search / Evaluation
   ↓
AI
   ↓
Подсказка
```

Это позволит использовать общие алгоритмы и избежать дублирования.

---

# 3. API подсказки

Добавить отдельный компонент, например:

```python
class HintEngine:
    ...
```

Рекомендуемый интерфейс:

```python
get_best_move(game: Game, player: str) -> tuple[int, int] | None
```

Например:

```python
move = hint_engine.get_best_move(game, PLAYER_X)
```

Если ход невозможен или игра завершена:

```python
None
```

---

# 4. Что считается оптимальным ходом

В первой версии под «оптимальным» понимать:

> ход, который имеет наилучшую оценку согласно используемому алгоритму поиска и эвристической оценки позиции.

Не утверждать, что алгоритм математически гарантирует абсолютно оптимальную игру во всех возможных состояниях 5×5, если используется ограниченный поиск.

В интерфейсе можно называть функцию:

```text
Подсказка
```

а не:

```text
Гарантированно лучший ход
```

---

# 5. Приоритеты поиска

Для игрока `X` использовать следующие приоритеты.

### 1. Немедленная победа

Если игрок может выиграть следующим ходом, подсказка должна указывать этот ход.

---

### 2. Блокировка

Если соперник `O` может выиграть следующим ходом, подсказка должна рекомендовать блокировку.

---

### 3. Создание угрозы

Если ход создаёт несколько потенциальных выигрышных комбинаций, он должен иметь высокий приоритет.

---

### 4. Позиционная оценка

Учитывать:

* центр;
* количество потенциальных линий;
* количество своих символов в потенциальных линиях;
* количество символов соперника;
* возможность создания будущих угроз.

---

### 5. Ограниченный поиск

Если архитектура уже содержит поисковый алгоритм для сложного AI, использовать его.

Предпочтительно:

```text
minimax + alpha-beta pruning
```

с ограниченной глубиной.

---

# 6. Единый движок поиска

Если в рамках предыдущего ТЗ реализован сложный AI с minimax, необходимо по возможности вынести алгоритм поиска в переиспользуемый компонент.

Например:

```text
search.py
```

с классом:

```python
class SearchEngine:
    ...
```

Пример интерфейса:

```python
get_best_move(
    game: Game,
    player: str,
    depth: int
) -> tuple[int, int] | None
```

Тогда:

```text
AI
 └── SearchEngine

HintEngine
 └── SearchEngine
```

Не копировать minimax в `AI` и `HintEngine`.

---

# 7. Поведение кнопки «Подсказка»

Добавить кнопку:

```text
[ Подсказать ход ]
```

Она должна находиться рядом с:

```text
[ Новая игра ]
```

или в отдельном блоке управления.

---

# 8. Условия доступности

Кнопка подсказки активна только когда:

* игра продолжается;
* сейчас ход игрока;
* пользователь ещё не сделал ход;
* AI не выполняет свой ход.

Если сейчас ход компьютера:

```text
Подсказка
```

не должна быть доступна.

---

# 9. Подсветка рекомендованной клетки

После нажатия «Подсказать ход»:

1. вычислить лучший ход;
2. визуально подсветить соответствующую клетку;
3. **не размещать X автоматически**;
4. оставить ход игроку.

Например:

```text
┌───┬───┬───┬───┬───┐
│ X │   │   │   │   │
├───┼───┼───┼───┼───┤
│   │ O │   │   │   │
├───┼───┼───┼───┼───┤
│   │   │[?]│   │   │
├───┼───┼───┼───┼───┤
│   │   │   │   │   │
├───┼───┼───┼───┼───┤
│   │   │   │   │   │
└───┴───┴───┴───┴───┘
```

Способ визуального выделения выбрать с учётом существующего UI.

---

# 10. Повторное нажатие

Если пользователь нажал:

```text
Подсказать ход
```

несколько раз подряд, не создавать несколько подсветок.

Должна существовать максимум одна активная подсказка.

При повторном запросе:

* пересчитать ход;
* обновить подсветку.

---

# 11. Сброс подсказки

Подсказка должна автоматически исчезать после:

### Хода игрока

Пользователь сделал ход → подсветка убирается.

### Хода компьютера

Перед началом хода AI подсказка должна быть сброшена.

### Новой игры

Все подсказки удаляются.

### Окончания игры

Подсветка подсказки должна быть удалена либо заменена подсветкой победной комбинации.

Предпочтительно:

```text
победная подсветка имеет приоритет над подсказкой.
```

---

# 12. Подсказка не должна раскрывать внутреннюю логику

Не требуется показывать пользователю:

* score;
* глубину minimax;
* оценку позиции;
* количество рассмотренных вариантов.

По умолчанию достаточно:

```text
Рекомендуемый ход подсвечен на поле.
```

---

# 13. Текстовый статус

После получения подсказки можно временно показать:

```text
Попробуйте сделать ход в подсвеченную клетку.
```

После хода игрока вернуть обычный статус:

```text
Ход компьютера...
```

или:

```text
Ваш ход
```

в зависимости от состояния игры.

---

# 14. Не выполнять ход автоматически

Это принципиальное требование.

Нажатие:

```text
Подсказать ход
```

никогда не должно приводить к:

```python
game.make_move(...)
```

Подсказка только показывает рекомендацию.

---

# 15. Взаимодействие с уровнями сложности

Функция подсказки должна быть независима от выбранного уровня сложности.

Например:

```text
Сложность: Простой
Подсказка: использует собственный алгоритм поиска лучшего хода
```

Пользователь должен иметь возможность играть на простом уровне и всё равно получать сильную подсказку.

---

# 16. Ограничение времени вычисления

Получение подсказки не должно зависать надолго.

Использовать тот же принцип ограниченного поиска, что и для сложного AI.

Если вычисление может быть относительно долгим:

* не блокировать UI;
* при необходимости выполнять расчёт через фоновую задачу;
* после завершения безопасно обновлять Tkinter UI через главный поток.

Для текущего проекта предпочтительно сначала использовать синхронный расчёт, если он укладывается в приемлемое время.

Не использовать:

```python
time.sleep()
```

для ожидания результата.

---

# 17. Поведение при отсутствии хода

Если игра завершена:

```text
get_best_move() -> None
```

UI не должен падать.

Если свободных клеток нет:

```text
None
```

# 18. Тестирование HintEngine

Добавить:

```text
tests/test_hint.py
```

или соответствующий раздел существующих тестов.

Минимальный набор:

### Немедленная победа

Позиция:

```text
X X X X .
```

Подсказка должна указать последнюю клетку.

---

### Блокировка

Позиция:

```text
O O O O .
```

Подсказка игрока `X` должна указать клетку, блокирующую победу `O`.

---

### Пустое поле

Подсказка должна вернуть допустимый ход.

Если центральная клетка является лучшим ходом согласно алгоритму:

```text
(2, 2)
```

она должна быть выбрана.

---

### Занятые клетки

Подсказка никогда не должна возвращать занятую клетку.

---

### Завершённая игра

После победы:

```python
get_best_move(...) is None
```

---

### Ничья

При заполненном поле:

```python
get_best_move(...) is None
```

# 20. UX-требования

Пользователь должен сразу понимать:

* что подсказка не делает ход за него;
* какая именно клетка рекомендована;
* что после собственного хода подсказка исчезнет.

Не использовать слишком агрессивную визуальную анимацию.

---

# 21. Совместимость с победной подсветкой

Если одновременно существуют:

```text
подсказка
```

и:

```text
победная линия
```

победная линия имеет приоритет.

После завершения игры подсказка не должна визуально мешать определению победной комбинации.

# 23. Архитектурные требования

Не помещать вычисление оптимального хода в `ui.py`.

Недопустимо:

```python
def on_hint_clicked(self):
    # огромный minimax внутри UI
```

Правильно:

```python
def on_hint_clicked(self):
    move = self.hint_engine.get_best_move(
        self.game,
        PLAYER_X
    )
    self.highlight_hint(move)
```

# 24. Definition of Done

Функциональность считается готовой, если:

* [ ] появилась кнопка «Подсказать ход»;
* [ ] кнопка работает только во время хода игрока;
* [ ] подсказка не выполняет ход автоматически;
* [ ] рекомендованная клетка визуально подсвечивается;
* [ ] подсказка исчезает после хода;
* [ ] подсказка исчезает при новой игре;
* [ ] подсказка корректно работает перед победой;
* [ ] подсказка умеет находить немедленный победный ход;
* [ ] подсказка умеет блокировать непосредственную победу соперника;
* [ ] подсказка не предлагает занятую клетку;
* [ ] после окончания игры подсказка недоступна;
* [ ] добавлены автоматические тесты;
* [ ] существующие тесты продолжают проходить;
* [ ] вычисление не блокирует UI на неприемлемое время;
* [ ] логика подсказки отделена от UI;
* [ ] README обновлён.
