# Дополнительное техническое задание №1

# Система уровней сложности игры

## 1. Цель

Расширить существующую игру «Крестики-нолики 5×5» возможностью выбора уровня сложности ИИ перед началом игры.

Должны быть доступны три уровня:

* **Простой**
* **Средний**
* **Сложный**

Выбор уровня сложности должен влиять именно на алгоритм выбора хода компьютера, а не только на визуальное поведение.

Существующая игровая логика `Game` не должна зависеть от уровня сложности.

---

# 2. Общий принцип архитектуры

Не создавать три полностью независимых класса ИИ с дублированием кода.

Предпочтительный вариант:

```text
AI
 ├── difficulty = EASY
 ├── difficulty = MEDIUM
 └── difficulty = HARD
```

или стратегия:

```text
AI
 └── DifficultyStrategy
      ├── EasyStrategy
      ├── MediumStrategy
      └── HardStrategy
```

Выбрать наиболее простой вариант, который хорошо соответствует существующей архитектуре проекта.

Главное требование:

> Изменение уровня сложности не должно требовать изменения `Game` или игрового UI-кода, кроме передачи выбранной настройки в AI.

---

# 3. Константы

Добавить в `constants.py`:

```python
DIFFICULTY_EASY = "easy"
DIFFICULTY_MEDIUM = "medium"
DIFFICULTY_HARD = "hard"
```

Для отображения пользователю использовать русские названия:

```text
Простой
Средний
Сложный
```

Не использовать русские строки непосредственно в игровой логике.

---

# 4. Уровень «Простой»

Цель — предоставить начинающему игроку ИИ, который не всегда играет оптимально.

ИИ должен:

* выбирать только свободные клетки;
* иногда использовать базовые эвристики;
* не обязан всегда блокировать победу игрока;
* не обязан всегда выбирать лучший ход.

При этом ИИ **никогда не должен нарушать правила игры**.

Допустимая реализация:

1. собрать доступные клетки;
2. часть базовых эвристик использовать с низким приоритетом;
3. в некоторых ситуациях выбирать не лучший ход.

Важно:

> «Простой» не означает намеренно делать недопустимые ходы или нарушать правила.

---

# 5. Уровень «Средний»

Средний уровень должен использовать уже реализованные эвристики.

Приоритеты:

1. собственный немедленный выигрыш;
2. блокировка немедленного выигрыша игрока;
3. создание потенциально выигрышных комбинаций;
4. центр;
5. другие стратегически выгодные клетки.

При этом допускается использование ограниченного поиска вариантов.

Например:

```text
глубина поиска = 1–2 хода
```

Если полноценный поиск существенно усложняет текущую архитектуру, допускается реализовать средний уровень исключительно на основе улучшенных эвристик.

Главное — обеспечить заметное отличие поведения от уровня «Простой».

---

# 6. Уровень «Сложный»

Сложный уровень должен стремиться выбирать наиболее сильный ход из доступных в пределах разумного времени выполнения.

Использовать комбинацию:

* немедленного поиска победы;
* блокировки соперника;
* оценки потенциальных линий;
* позиционной оценки;
* ограниченного поиска будущих ходов.

Допускается использовать:

```text
minimax
```

с ограничением глубины и/или эвристической оценкой позиции.

Не требуется реализовывать математически совершенный игровой ИИ.

---

# 7. Ограничение времени

ИИ не должен заметно зависать при расчёте хода.

Для обычного пользовательского компьютера один ход должен рассчитываться практически мгновенно.

Не использовать бесконтрольный полный перебор дерева игры.

Если используется minimax:

* ограничить глубину;
* использовать alpha-beta pruning;
* ограничить количество рассматриваемых ходов при необходимости;
* использовать эвристическую оценку позиции.

---

# 8. Фабрика создания ИИ

Предпочтительно создать единый способ создания AI:

```python
AI(difficulty=DIFFICULTY_MEDIUM)
```

или:

```python
create_ai(difficulty)
```

Например:

```python
ai = AI(DIFFICULTY_HARD)
```

Интерфейс выбора сложности не должен знать детали алгоритма.

---

# 9. Пользовательский интерфейс

Добавить в UI элемент выбора сложности.

Предпочтительно использовать:

```python
ttk.Combobox
```

или `ttk.Radiobutton`.

В интерфейсе должно отображаться:

```text
Уровень сложности:

[ Средний ▼ ]
```

Варианты:

```text
Простой
Средний
Сложный
```

По умолчанию:

```text
Средний
```

---

# 10. Момент изменения сложности

Рекомендуемое поведение:

* пользователь выбирает уровень;
* выбранный уровень применяется к **следующей игре**;
* текущая партия не должна неожиданно менять поведение ИИ в середине игры.

Если пользователь изменил сложность во время партии, можно:

### Вариант A — предпочтительный

Показать/оставить выбранную настройку, но применить её после нажатия:

```text
Новая игра
```

### Вариант B

Автоматически начать новую игру после изменения сложности.

Выбрать вариант A, если он не противоречит существующему UI.

---

# 11. Отображение текущей сложности

Рекомендуется показывать текущую настройку:

```text
Игрок: X
Компьютер: O
Сложность: Средний
```

---

# 12. Интеграция с существующей архитектурой

`Game` не должен знать о сложности.

То есть недопустимо:

```python
game.make_move(..., difficulty=...)
```

Сложность относится исключительно к AI.

Предпочтительно:

```python
game = Game()
ai = AI(difficulty=DIFFICULTY_HARD)

move = ai.get_move(game)
```

# 13. Тестирование

Добавить:

```text
tests/test_ai.py
```

или расширить существующий файл.

Проверить:

### Общие тесты

Для каждого уровня:

* AI возвращает допустимый ход;
* AI не выбирает занятую клетку;
* AI не падает на пустом поле;
* AI корректно работает с частично заполненным полем.

### Простой

Проверить, что AI соблюдает правила.

Не требовать от него оптимальной игры.

### Средний

Проверить:

* выбор немедленного победного хода;
* блокировку непосредственной угрозы;
* предпочтение стратегически выгодного хода.

### Сложный

Проверить:

* победный ход;
* блокировку;
* работу ограниченного поиска;
* отсутствие недопустимых ходов.

Тесты не должны проверять случайные детали внутренней реализации.

---

# 14. Регрессионные требования

После добавления сложности должны продолжать проходить все существующие тесты.

Особенно:

* `Game` не изменяет правила;
* победа работает;
* ничья работает;
* новая игра работает;
* UI не позволяет сделать ход после окончания партии.

---

# 15. Definition of Done

Функциональность считается готовой, если:

* [ ] есть три уровня сложности;
* [ ] пользователь может выбрать уровень через GUI;
* [ ] по умолчанию выбран «Средний»;
* [ ] выбор влияет на поведение AI;
* [ ] `Game` не зависит от сложности;
* [ ] уровни не содержат неоправданного дублирования кода;
* [ ] сложный уровень не вызывает заметного зависания интерфейса;
* [ ] AI всегда делает допустимые ходы;
* [ ] добавлены автоматические тесты;
* [ ] существующие тесты продолжают проходить;
* [ ] README обновлён;
* [ ] в README описаны три уровня сложности.
